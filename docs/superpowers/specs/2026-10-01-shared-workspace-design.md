# qwerty 공동 사용 설계

## 목적과 확정된 요구사항

- 사용자와 가족 1명이 같은 매물·사진·캘린더 일정·메모를 조회하고 등록·수정·삭제함.
- 이메일 회원가입 없이 공용 비밀번호 입력으로 접속함.
- 사용자가 지정한 비밀번호는 서버 환경변수로만 설정함. 소스·GitHub·문서·로그에 실제 값을 남기지 않음.
- 밤/낮 모드, 검색어, 정렬, 선택한 화면은 각 브라우저의 개인 설정으로 유지함.
- 캘린더 메모는 입력칸과 저장된 내용을 모두 크게 읽을 수 있도록 개선함.
- 실제 서비스: https://qwerty-gilt-rho.vercel.app/
- GitHub: https://github.com/sypyun-a11y/qwerty

## 가장 중요한 안전 조건

2026-10-01 사용자가 현재 작성 중인 사람이 없음을 확인하고 작업 진행을 허용함. **기존에 저장된 데이터는 계속 보존해야 함.**

1. 메모 가시성·OG 주소 수정은 기존 저장 구조를 유지하여 실제 서비스에 반영 가능함. 공동 저장 기능은 별도 브랜치와 테스트 배포에서 개발·검증 후 전환함.
2. 기존 기기 브라우저의 IndexedDB를 삭제·비우거나 새 데이터로 덮어쓰지 않음.
3. 이미 등록된 데이터와 아직 등록하지 않은 입력은 구분함. 현재 열린 이전 버전의 미등록 입력을 원격으로 자동 백업할 수 있다고 약속하지 않음.
4. 실제 전환 전 두 사용자의 작성 중인 내용을 등록·저장했는지 확인함. 새로고침을 강제하거나 자동 실행하지 않음.
5. 전환 후 기존 브라우저 기록을 파일로 백업한 뒤 사용자가 선택하여 공동 저장소에 이관함. 원본은 그대로 남김.
6. 먼저 이관된 레코드를 나중 이관이 덮어쓰지 않음. 같은 ID가 이미 존재하거나 삭제된 이력이 있으면 충돌 안내 후 건너뜀.
7. 테스트 데이터와 실제 공동 데이터는 분리함. 테스트·검증 코드가 실제 레코드를 삭제하지 않음.

## 구성

### 화면

기존 단일 HTML 화면과 브랜드를 유지함. 서버 기능만 별도 API로 추가함. 별도 프레임워크로 전체 화면을 재작성하지 않음.

첫 접속은 비밀번호 입력 화면이며, 인증 후 기존 매물·캘린더·메모 화면을 보여줌. 공유 연결 상태와 저장 성공 여부를 명확히 표시함. 네트워크 오류를 저장 성공으로 표시하지 않음.

### 공동 저장소

확인된 개인 Vercel 프로젝트 `sypyun-1353s-projects/qwerty`에 Marketplace 관리형 Neon Postgres를 연결하는 구성을 제안함. 공개적으로 확인된 `free_v3` 무료 플랜, 별도 이메일 인증 기능은 비활성화함. 유료 플랜을 자동 선택하지 않음. 실제 설치와 서버 환경변수 설정을 완료한 뒤 해당 리소스를 대상으로 구현함. 설치가 사용자 계정 동의를 요구하면 중단하고 안내함.

매물·일정·메모를 각각 레코드로 저장함. 브라우저의 전체 목록을 통째로 서버에 덮어쓰지 않음. ID·버전·서버 수정 시각·삭제 이력을 유지하여, 서로 다른 레코드의 수정은 공존하고 동일 레코드 충돌은 알림으로 처리함.

사진은 별도 레코드로 저장하고 인증된 API를 통해 제공함. 기존 압축을 유지하고 사진 한 장씩 업로드하여 Vercel 요청 크기 제한을 넘지 않게 함. 사진 업로드가 끝나기 전에 등록 완료를 처리하지 않음. 무제한 크기·개수의 업로드는 허용하지 않음.

### 공용 비밀번호와 접속 보호

- 비밀번호는 서버에서만 검증함. 브라우저 코드의 단순 비교·localStorage 인증값으로 보호하지 않음.
- 저장된 비밀번호는 salt와 강한 해시를 사용함. 세션 서명용 비밀값은 비밀번호와 별도로 생성함.
- 인증 세션은 서명된 HttpOnly·Secure·SameSite 쿠키를 사용함. 미인증 요청의 데이터 조회·변경·사진 조회를 서버에서 거절함.
- 짧은 비밀번호의 반복 추측을 줄이기 위해 로그인 실패 횟수를 제한함. 오류는 비밀번호 존재 여부를 과도하게 노출하지 않음.
- 다른 사이트에서의 쓰기 요청을 차단하고 요청 Origin을 검사함.
- 공용 비밀번호이므로 개인별 작성자 구분은 제공하지 않음.

### 자동 반영과 충돌

공유 화면을 수초 간격으로 자동 갱신하며, 탭에 다시 돌아올 때도 최신 데이터를 조회함. 불필요한 상시 연결이나 복잡한 이벤트 스트리밍은 도입하지 않음.

다른 기기에서 바뀐 내용이 현재 사용자의 작성 중인 입력칸을 초기화하지 않게 함. 같은 레코드의 버전이 달라졌다면 저장을 거절하고 내용 비교·재확인 안내를 보여줌. 현재 초안은 유지함. 새 버전의 등록 초안과 메모 입력은 브라우저에 임시 보존함.

메모 입력은 화면에서 즉시 반영하고 공유 저장은 짧게 묶어 실행하되, 저장 대기 중인 입력은 임시 보존하여 새로고침 후 복구함. 공동 메모는 같은 글을 동시에 수정하는 실시간 공동편집기가 아니며, 충돌 시 조용히 덮어쓰지 않음.

## 검증 기준

- 비밀번호 없이 목록·일정·메모·사진 API에 접근할 수 없음.
- 올바른 비밀번호로 서로 다른 두 브라우저가 같은 데이터를 조회함.
- A에서 등록·수정·삭제한 내용이 B에 자동 반영됨. 반대 방향도 확인함.
- A와 B가 다른 레코드를 동시에 수정해도 한쪽의 변경이 사라지지 않음.
- 동일 레코드 동시 수정은 충돌을 표시하고 작성 중인 입력을 보존함.
- 사진 여러 장, 일정 4종 태그, 메모, 밤/낮 모드, 모바일 기능을 유지함.
- 새로고침·네트워크 오류·저장 실패에서 데이터와 초안을 보호함.
- 기존 브라우저 기록의 백업·이관 후에도 원본이 남아 있음.
- 실제 서비스 변경은 별도 확인을 받고 진행하며, 기존 배포로 되돌릴 수 있게 함.
